# M5：OpenAI 兼容服务

## 目标

把已通过 M4 的检索核心封装为清小搭可调用的 OpenAI 兼容服务，同时保持核心算法与协议层解耦。

## 前置门禁

- M4 状态为 `COMPLETE` 且结论为 Go。
- 实现开始时重新核对清小搭最新接入指南并把版本/日期记录到证据；未取得指南时可以完成本地契约测试，但不得声明平台通过。

## 任务

### M5-T01：模型与聊天协议

实现：

- `GET /v1/models`
- `POST /v1/chat/completions`
- 稳定错误结构
- 流式与非流式响应

通过标准：契约测试覆盖请求校验、流式结束标记、客户端断开、超时和内部错误；核心输出在两种模式下语义一致。

### M5-T02：Bearer 鉴权与安全日志

实现配置化 token 校验、缺失/错误 token 拒绝和敏感信息脱敏。

通过标准：token、Cookie、Authorization header 和用户隐私字段不出现在日志、异常或证据报告中。

### M5-T03：项目状态与并发

通过 `project_id` 关联服务器状态，确保重复请求幂等、并发迁移原子、服务重启可恢复。

通过标准：并发测试证明同一项目不会重复进入检索轮次；重启恢复后允许动作与重启前一致。

### M5-T04：平台探测

执行清小搭 L0 或当时官方等价探测，记录所有请求、响应码、耗时和限制，不记录密钥。

通过标准：

- `/v1/models` 通过真实平台探测。
- chat 流式和非流式均通过。
- 平台允许时间内完成或诚实返回异步/重试语义。
- 真实平台不可访问时标记 `real_external: not_run`，M5 不完成。

## 阶段证据

`evaluation/reports/m5-validation.json` 必须把本地协议测试、并发测试、真实平台探测和安全审计分开。
